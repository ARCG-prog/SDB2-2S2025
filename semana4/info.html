Introducción a las Estrategias de Recuperación

Esta sección establece los cimientos, definiendo qué es la recuperación de datos, por qué es crucial para cualquier negocio y los conceptos clave que rigen cualquier estrategia de protección de la información. Explora las causas más comunes de pérdida de datos y cómo los objetivos de RPO y RTO determinan el enfoque a seguir.

¿Qué es la Recuperación de Datos?

Es el proceso de rescatar y restaurar información inaccesible, perdida o corrupta. Los objetivos principales son:

  • Minimizar la pérdida de datos.
  • Reducir el tiempo de inactividad (downtime).
  • Garantizar la continuidad del negocio.
  • Restaurar el sistema a un estado consistente.

Causas Comunes de Pérdida de Datos

RPO: Objetivo de Punto de Recuperación

Pregunta: ¿Cuánta información podemos permitirnos perder?

Mide la cantidad máxima de datos perdidos, medida en tiempo. Un RPO de 1 hora significa que se perderán como máximo los datos de la última hora.

RTO: Objetivo de Tiempo de Recuperación

Pregunta: ¿Cuánto tiempo podemos estar inactivos?

Mide el tiempo máximo que un sistema puede estar caído después de un fallo. Un RTO de 2 horas significa que el sistema debe estar operativo en menos de 2 horas.

Recuperación con Respaldos Completos

Aquí exploramos el tipo de respaldo más fundamental: el respaldo completo. Aprenderás qué es, cómo funciona su proceso de creación y restauración, y verás ejemplos prácticos de código. Aunque es el método más simple, es crucial entender sus ventajas y desventajas para construir una estrategia sólida.

¿Qué es un Respaldo Completo?

Un respaldo completo (Full Backup) es una copia exacta de todo el conjunto de datos en un momento específico. Es la base para otras estrategias y el más simple de restaurar, pero también el que más tiempo y espacio consume.

Práctica: Crear un Respaldo Completo

SQL Server (T-SQL)

BACKUP DATABASE MiEmpresaDB TO DISK = 'D:\Backups\MiEmpresaDB_Full.bak' WITH NAME = 'Respaldo Completo de MiEmpresaDB', DESCRIPTION = 'Respaldo completo semanal'; GO

PostgreSQL (pg_dump)

pg_dump -U miusuario -F c -b -v -f D:\Backups\MiEmpresaDB_Full.backup MiEmpresaDB

Práctica: Restaurar un Respaldo Completo

SQL Server (T-SQL)

USE master; GO RESTORE DATABASE MiEmpresaDB FROM DISK = 'D:\Backups\MiEmpresaDB_Full.bak' WITH REPLACE; GO

Ventajas: Restauración simple y rápida.

Desventajas: Consume mucho espacio, es lento de crear y se pierden todos los datos desde el último respaldo.

Respaldos Diferenciales y de Log (Incrementales)

Esta sección detalla estrategias más eficientes que el respaldo completo. Mediante botones interactivos, podrás comparar cómo funcionan los respaldos diferenciales y los de log de transacciones, entendiendo sus procesos de restauración y cómo ayudan a minimizar la pérdida de datos (RPO) y optimizar el uso de almacenamiento.

Respaldo Diferencial

Contiene todos los cambios realizados desde el último respaldo completo. Cada nuevo respaldo diferencial es más grande que el anterior dentro del mismo ciclo.

Proceso de Restauración:

Se necesitan solo 2 archivos: el último respaldo completo y el último respaldo diferencial.

-- 1. Restaurar el COMPLETO sin recuperar RESTORE DATABASE MiEmpresaDB FROM DISK = '..._Full.bak' WITH NORECOVERY; GO -- 2. Aplicar el último DIFERENCIAL y recuperar RESTORE DATABASE MiEmpresaDB FROM DISK = '..._Diff_Latest.bak' WITH RECOVERY; GO

Respaldo de Log de Transacciones (Incremental)

Contiene todas las transacciones ocurridas desde el último respaldo de log. Permite una recuperación granular (a un punto en el tiempo) y minimiza la pérdida de datos.

Proceso de Restauración:

Se necesita una cadena ininterrumpida: el último completo, opcionalmente el último diferencial, y TODOS los respaldos de log posteriores.

-- 1. Restaurar Completo (NORECOVERY) -- 2. Restaurar Diferencial (NORECOVERY) -- 3. Restaurar Log 1 (NORECOVERY) -- 4. Restaurar Log 2 (NORECOVERY) -- 5. ... -- 6. Restaurar Último Log (RECOVERY)

Técnicas Avanzadas de Recuperación

Más allá de los respaldos básicos, existen técnicas avanzadas para escenarios críticos. Esta sección interactiva te permite desplegar y conocer en detalle la recuperación a un punto en el tiempo (PITR), la replicación de datos y el clustering de alta disponibilidad, entendiendo cómo cada una aborda los desafíos de RPO y RTO.

Permite restaurar una base de datos a un momento exacto, ideal para corregir errores humanos. Requiere respaldos de log.

Escenario: Borrado accidental a las 10:05 AM. Restaurar a las 10:04 AM.

-- Restaurar a una copia para no tocar la producción RESTORE DATABASE MiEmpresaDB_Copia ... WITH NORECOVERY; RESTORE LOG MiEmpresaDB_Copia ... WITH NORECOVERY; RESTORE LOG MiEmpresaDB_Copia ... WITH STOPAT = '2025-08-14T10:04:00', RECOVERY;

Mantiene una copia (réplica) de la base de datos en un servidor secundario.

  • Síncrona: Cero pérdida de datos (RPO=0) pero puede añadir latencia.
  • Asíncrona: No impacta el rendimiento pero hay riesgo de pérdida mínima de datos.

Un grupo de servidores que trabajan juntos para aumentar la disponibilidad. Si el servidor activo falla, uno pasivo toma su lugar automáticamente (failover). Ofrece un RTO muy bajo (segundos a minutos) pero no protege contra corrupción de datos.
